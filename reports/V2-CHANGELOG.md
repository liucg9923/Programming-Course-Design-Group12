## 🔧 详细修改清单

### 修复 1：`register.cpp` — 挂号扣款

**问题**：原代码挂号后未扣除 `patient->balanceCents`，也未累加 `g_hospitalRevenue`。

**修改**：
- 在生成挂号记录之前增加**余额校验**：余额 < 挂号费时拒绝挂号并提示
- 在 `appendRecord(rec)` 之后增加 2 行：
  ```cpp
  patient->balanceCents -= regFee;     /* 扣除患者余额 */
  g_hospitalRevenue    += regFee;      /* 累加医院营收 */
  ```
- 挂号成功凭证增加**当前余额显示**

**附带改进（建议 A）**：重构 `listDoctorsOnDuty()`，接受 `patient` 参数后在医生列表里**直接显示每位医生是否可挂**：
- `(号已满)` — 该医生今日挂号达上限
- `(本科室今日已挂)` — 同一患者同科室已挂过
- `(余额不足)` — 患者当前余额不够挂号费

同时增加挂号费列，让用户选医生时心中有数。

---

### 修复 2：`see_doctor.cpp` — 检查/开药扣款

#### 2A. 开检查（`doExamination`）

**问题**：原代码 `g_hospitalRevenue += fee;` 已加，但 `patient->balanceCents -= fee;` 漏了。

**修改**：
- 创建检查记录前增加**余额校验**
- 扣费与营收累加同步进行
- 输出中显示剩余余额

#### 2B. 开药（`doPrescription`）

**问题**：同上。且**扣库存放在扣款前**，当时设计导致"库存已扣但余额不够"时需要复杂回滚。

**修改**：
- **先校验余额**（余额不足则直接返回，不需要扣库存后再回滚）
- 然后再调用 `DeductMedicineStock`
- 成功创建记录后扣款、累营收
- 输出中显示剩余余额

---

### 修复 3：`see_doctor.cpp` — 记录更正（红冲机制）

**问题**：原 `modifyRecordByRevoke()` 只做了 `oldRec->isRedInk = 1;`，但：
- ❌ 旧记录的药品库存没恢复
- ❌ 旧记录的金额没退给患者
- ❌ 旧记录的营收没扣减
- ❌ 新记录的库存没从药房扣
- ❌ 新记录的金额没扣患者余额

这是违反"红冲"会计原则的 —— 红冲必须让财务/库存完全回到作废前状态。

**修改**（5 步法）：
```
步骤 1：回滚旧记录 → 退款、退营收、退库存
步骤 2：构造新记录（复制旧记录，换记录 ID 和时间戳）
步骤 3：验证患者余额是否足够支付新记录（不够则全部回滚）
步骤 4：应用新记录 → 扣款、加营收、扣库存
步骤 5：标记旧记录红冲 + 追加新记录到链表
```

每一步失败都做**完整回滚**，保证数据一致性。

此外限制了更正类型，只允许修改"检查 / 开药 / 看诊"这 3 类有财务影响的记录，不允许直接改挂号/住院/出院结算记录。

---

### 应用建议 B：`billing.cpp` — 营业额实时累加

**改动 1**：`runDailyAutoCharge()` 第 192 行，每日扣费时增加：
```cpp
g_hospitalRevenue += ip->dailyFeeCents;   /* 实时入营收 */
```

**改动 2**：`dischargePatient()` 第 244 行，出院当天补扣时同样加入营收：
```cpp
g_hospitalRevenue += todayCharge;
```

**改动 3**：`dischargePatient()` 第 281 行，**删除**原先的一次性累加 `g_hospitalRevenue += ip->totalChargedCents;`，避免重复累加。

**结果**：管理视角统计的"医院总营业额"现在**实时反映**住院扣费，不再等出院结算才一次性入账。
